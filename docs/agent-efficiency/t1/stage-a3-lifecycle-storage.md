# T1 stage A3 — immutable lifecycle storage

2026-11-18. Scoped task contract under issue #23 owner approval 6952955719: add cohort manifest, lifecycle root and event-chain storage with negative tests and a bounded index probe. Follow A2 review [210565014](https://github.com/shmtoan08/SoftwareFactory/commit/ca2d570ae847e28e578c3f88bb6760d142b6382f#commitcomment-210565014), which accepted A2 and authorized continuation of stage A. This slice does not complete stage A or T1.

Migration 0019 adds three telemetry tables owned by telemetry_owner with FORCE RLS, no policies and no grants to runtime/service groups. Even a provisioned ingestor can register calls but cannot enroll a lifecycle, publish a manifest or close a root. No operator login, lifecycle API, existing task schema/permission change or runtime hook is introduced. TASK_BOUND remains disabled. Services must not treat a storage row or an event name as proof of admission or eligibility.

The immutable cohort manifest stores a protected contract reference/key version, bounded operator/version references, source SHA, finite approval time, planned counts, size and five independent risk flags. SQL enforces S <=5 files/1 package, M <=20 files/3 packages excluding S, L above those limits, and unclassified when either count is unknown. Risk never changes size; ordinary means all five flags are false. A root uses same-project task/manifest foreign keys and permits only one root per task and one use of a manifest. Reopening must retain that root rather than create another sample. No raw contract or prompt is stored.

Event storage enforces a unique project/root/sequence and a same-project/root predecessor sequence+digest FK. Only sequence1 may be OPEN; later events require their immediate predecessor, with no sequence gaps or null predecessor bypass. CLOSE requires a bounded terminal disposition; CENSOR requires a finite cutoff no later than its observation time and cannot carry a terminal outcome. UPDATE/DELETE/TRUNCATE are rejected, including privileged fixture attempts. Project/root/sequence uniqueness supplies the scoped event index; no redundant equivalent index is added.

These are **structural constraints only**. Storage does not yet prove pre-run approval, compute authentic event digests, validate transition order, preserve amendment deviation payloads, reconcile settlement/coverage, derive service_actor_ref or establish terminal workflow authority. CLOSE/REOPEN names are reserved storage shapes with no service entry point. Only admin test fixtures populate them in this slice. Later typed lifecycle functions must establish those semantic checks before opening access; no task enrollment or closure is authorized by this migration alone. Lifecycle retention anchors/holds and report reopening logic remain future work, with no deletion grants/job.

A2 review follow-ups are included as a forward replacement of register_call in migration0019, leaving applied0018 unchanged: invalid provider and non-hex HMAC now return 22023 consistently before INSERT, with executable negative tests. CI step naming now covers authority and lifecycle storage.

Validation: local PostgreSQL17 migration/reapply, A2 regression and A3 SQL fixture passed; fixtures roll back. A3 tests include exact size boundaries/null/negative counts, cross-project task/manifest/event references, duplicate roots/events, missing/bad predecessors, OPEN/CLOSE/CENSOR shape constraints, immutable writes, actual provisioned-service denial, owner FORCE RLS denial and app_runtime GUC/escalation denial. ACL checks cover all service groups. The synthetic probe adds 4,000 roots/manifests/events across two projects plus a five-event chain, then EXPLAIN ANALYZE checks a project/root/sequence page (LIMIT100): an index condition, no sequential scan, four returned rows. This verifies this lookup on a bounded admin fixture, not production throughput, lifecycle-service RLS cost or observer overhead. PG16/17 CI repeats0019 and runs the same fixture before the existing full regression suite.
