# T1 stage A6 — locked report storage and bounded readers

2026-11-19. Scoped task contract under issue #23 owner approval 6952955719 and the owner's instruction to continue after A5: report/member storage and typed project-scoped call-level reads. A5 review [210645707](https://github.com/shmtoan08/SoftwareFactory/commit/b7f5f74f1aa47d8c32d70b0f7fb70aade1386a50#commitcomment-210645707) arrived during implementation and accepted A5 without findings. Its PG16/17, Linux and gVisor checks passed, while native Codex remained queued for a hosted runner. This does not imply complete CI or T1 acceptance.

Migration 0022 adds immutable reports and report_members, both FORCE RLS with no policies, grants or publisher. Report membership uses a same-project report FK and lifecycle/sequence/digest watermark FK, unique per report/root. Supersession is same-project and cannot reference itself. Cutoff/finalization times must be finite and cutoff cannot exceed finalization. Protected digests remain internal. Mapping-version inventories are one-dimensional, distinct, bounded arrays (1–32 identifiers, each <=128 bytes).

The aggregate shape is a strict object with exactly total_roots, complete_roots, incomplete_roots, censored_roots and canonical_total. Counts are canonical nonnegative decimal strings of at most 30 digits. Censored roots are a **subset of incomplete roots**, not an additional denominator: total = complete + incomplete, censored <= incomplete. Until authority/coverage/mapping are proved, CHECK requires complete_roots = 0 and canonical_total = null. Unknown/free-text fields and invented available totals are rejected.

These are structural constraints, not verified reporting semantics. Only admin fixtures populate reports. There is no function accepting a caller-provided report body, and no report reader/publication endpoint. The future reconciler must compute aggregates/membership, verify event chronology/cutoff, supersession order/cycles, root outcomes, lifecycle reopening, mapping versions and independent inventory. A valid FK alone does not prove the referenced event predates cutoff, nor does a well-shaped aggregate prove membership counts match. No service can publish through this slice.

Two SECURITY DEFINER functions are executable only by telemetry_reporter with an authenticated LOGIN/registry read binding. read_observations scopes project and invocation, uses a complete (revision,kind) cursor, orders ascending and limits pages to 1–100 rows. It returns only sanitized usage metadata, including reported_total as TEXT to preserve exact integers and null for missing totals. No protected prompt reference, content digest, raw error, price or inferred canonical total is exported. read_settlement returns at most one immutable link plus has_quality_flags; false means only that no marker is visible at that statement snapshot, **not** complete coverage, successful execution or baseline eligibility. Missing links return no row. Both functions deny foreign project requests; a foreign/unknown invocation within an authorized project yields no row without revealing existence.

Only the function owner's read policies are extended. Reporter gains no direct table or ledger privilege, writer gains no reader EXECUTE, and no report/lifecycle write permission is opened. Existing ingest policies still require ingest binding. Keyset queries split first/subsequent pages so a generic plan can retain the cursor range predicate. The earlier observation index (project,invocation,revision) is replaced by its complete (project,invocation,revision,kind) order; a scoped quality-flag index supports EXISTS. These are live diagnostic pages, not a frozen report inventory: late lower-revision inserts may belong to earlier pages. Reproducible reports require the future cutoff/watermark reconciler. The service adapter must set the <=2s statement deadline before invoking SQL and serialize BIGINT revision cursors exactly; no transport/HTTP layer is introduced here. Bounded existing payloads plus <=100 rows keep diagnostic data below the contract's 1 MiB response budget, excluding any future transport envelope.

Local PostgreSQL17 migration/reapply, reader/report tests and A4/A5 SQL regression passed. Tests cover keyset boundaries, exact >JS-safe reported total, null versus zero, conflict flag visibility, foreign scope/invocation, writer/worker/direct SQL denial, registry revocation, denied arbitrary publication, report owner FORCE RLS, duplicate membership, wrong event sequence/digest, cross-project supersession, unknown aggregate keys and unavailable canonical state. A synthetic 4,000-observation/two-project fixture probes a deep page: EXPLAIN ANALYZE uses the composite cursor index, no sequential scan, returns 25 rows (local planner chose bitmap lookup of 54 matches plus a small sort). The actual authenticated reader also returns 25. This is bounded fixture evidence, not a production latency or constant-cost claim. CI applies 0022 twice and runs these tests on PG16/17 before full regression.

Next: trusted service context/HMAC binding and lifecycle protocol, independent coverage/reconciliation, deterministic report publication, verified mapping fixtures and disabled optional observation hooks. No live collection, provider call, T2 activation, report publication or T1/S0-B acceptance is enabled by A6.
