# T1 stage A5 — explicit call-level ledger settlement

2026-11-18. Scoped task contract under issue #23 owner approval 6952955719: immutable settlement storage, typed invocation/ledger identity validation, concurrent duplicate/conflict tests and least-privilege ledger access. A4 review [210632390](https://github.com/shmtoan08/SoftwareFactory/commit/5a8fbda0d3a9b095e9b3127ce04829d13e400042#commitcomment-210632390) accepted continuation; its wording note is fixed to describe GUC being ignored and authority deriving from the registry.

Migration 0021 adds settlements with unique (project,invocation) and (project,ledger_call), a same-project invocation FK and the existing ledger call primary-key FK. The typed function checks ledger project and identity; no new ledger unique index or field is needed. Direct table grants remain absent, FORCE RLS applies and updates/deletes/truncation are forbidden. A privileged administrator can bypass RLS, so the single-column ledger FK alone is not a claim of composite project validation: runtime validation is performed by the only granted function.

`link_ledger(project,invocation,ledger)` requires the authenticated ingestor login and registry binding. It reads the exact ledger ID rather than inferring a link from timestamps/task IDs, and checks cost session, nullable pipeline/task (null-safe equality), provider, model, prompt ID and prompt version. All existing finalized ledger outcomes are represented, including blocked/validation/provider-failure paths. The ledger outcome is read by the function, never supplied by the caller. A successful link is call-level historical metadata: it does not claim actual usage, settled invoice, TASK_BOUND or lifecycle completeness.

Matching prompt ID/version is **not** cryptographic proof that the invocation's protected prompt HMAC matches the ledger template fingerprint. This slice neither reads nor exports the legacy plain prompt/request hashes. The future trusted call closure must derive the invocation HMAC and ledger template from the same server context and prove that binding before verified lifecycle eligibility. Service callers currently remain trusted to supply the explicit finalized call ID. No hooks or service login provisioning are activated here; there is no historical backfill.

To perform DB identity validation, the non-login telemetry_owner receives column-only SELECT on ledger call/project/cost-session/pipeline/task/provider/model/prompt-ID/version/status. Ingestor/reporter/operator gain no ledger privilege. Because the legacy SELECT policy applies to PUBLIC and permits app GUC scope, a new owner-only **restrictive** policy requires the service registry in addition to a matching owner-only permissive policy. Thus a legacy GUC cannot OR around the new authority check. Existing app_runtime policy/grants and ledger rows are unchanged. No hash, request, error, token or cost columns are granted to the function owner; no ledger write privilege is granted.

Identical retries return duplicate and the original settlement ID; a first link returns recorded. Missing/foreign/mismatched ledger identities return mismatch with a normalized ledger-link-mismatch marker, without revealing whether an unauthorized ledger exists. Reassigning an invocation or using one ledger for a different invocation returns conflict, preserving the first link. These paths return bounded dispositions instead of raising after writing markers; callers must commit to preserve evidence. A partial unique index deduplicates repeated mismatch/conflict markers. Missing markers after rollback/crash still require independent inventory reconciliation; marker counts alone cannot prove coverage.

Real-PG tests cover all five ledger outcomes, each identity mismatch (including NULL task/pipeline versus non-NULL), foreign/missing ledgers, duplicate/conflicting links, one-ledger-per-invocation, role/revocation/direct-SQL denial, immutable history, and the restrictive policy defeating the legacy GUC for the function owner. They verify protected ledger columns remain inaccessible, compare the full ledger snapshot before/after, and confirm the existing app_runtime scoped ledger read still works. The shared two-connection harness adds settlement mode: uncommitted first link with a blocked second connection, then duplicate, same-invocation conflict and same-ledger/different-invocation conflict after commit. Its disposable database/role are removed. PG16/17 CI runs migration twice, SQL and both observation/settlement concurrency modes before full regression.

Remaining work includes report storage/readers, trusted service HMAC/context binding, lifecycle authority/transition/closure protocol, independent coverage reconciliation, mapping verification and bounded observer hooks. A5 itself introduces no provider call, execution-path wait/retry, runtime collector, retention job, T2 activation or S0-B/T1 completion claim.
