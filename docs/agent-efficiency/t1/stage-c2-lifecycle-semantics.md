# T1 C2 — authenticated lifecycle semantics with fail-closed closure

Migration 0024 extends the operator-maintained service registry with an `operator` capability and opens only typed SECURITY DEFINER entry points to `telemetry_operator`. No login, credential or registry row is provisioned by migration. The authenticated `session_user` must be a non-elevated LOGIN, hold the matching role membership and exact project registry binding, and must not be an `app_runtime` member. Ingest, reporter, app runtime and direct table paths remain denied.

`open_lifecycle` serializes by project/task, requires the task to remain `Ready` with lease epoch zero, derives approval time and actor from the database server/session, inserts the immutable manifest/root/OPEN event atomically and returns recorded/duplicate for exact retries. A changed retry conflicts. The operator supplies bounded protected references, source SHA, size inputs and independent risk flags; SQL remains authoritative for the S/M/L/unclassified classification. This does not enroll a task into telemetry usage eligibility or authorize execution.

`append_lifecycle_event` serializes by project/root and permits AMEND or CENSOR while the root is open, and REOPEN only immediately after CLOSE. It allocates the next sequence and server digest over the complete predecessor, server time, actor and cutoff. Exact event retries are duplicates; reuse with changed content conflicts. CENSOR requires a finite cutoff between root creation and server time and is reporting-only. An AMEND marker records chronology but the current approved schema has no protected deviation payload; therefore it is not sufficient deviation evidence for baseline eligibility.

`close_lifecycle` validates operator/project/root/outcome, then always rejects with `23514 Lifecycle coverage authority unavailable`. Candidate/observation tables cannot detect a chargeable call that bypassed observer creation, and CALL_ONLY invocations have no authoritative lifecycle/execution/lease binding. Treating an empty visible set as complete would be unsafe. TASK_BOUND remains blocked by the existing schema check. An approved independent dispatch inventory and generation binding are required before a later migration may introduce successful closure.

Real PostgreSQL tests cover direct-table denial, foreign project and wrong-role denial, started-task rejection, exact enrollment/event replay, immutable conflict, actor derivation, predecessor digest chain, AMEND/CENSOR/REOPEN transition order, invalid cutoff, close denial for every otherwise empty root, app_runtime contamination, grants and migration reapplication. A disposable cloned database test holds the same advisory locks from separate connections and proves concurrent identical enrollment returns recorded/duplicate while concurrent events commit as sequences 2 and 3 with an intact chain.

No production operator login, runtime endpoint, lifecycle CLOSE, TASK_BOUND upgrade, provider call, mapping promotion, report publication, retention deletion, T2 activation or S0-B acceptance is included.

Review follow-up migration 0025 keeps 0024 immutable and wraps its entry points: NULL protected HMAC/source SHA/task size and NULL close outcome now return consistent 22023 validation errors, while event replay takes the lifecycle advisory lock before duplicate lookup. The concurrent fixture proves two identical event IDs now serialize to recorded/duplicate rather than racing on the primary key.
