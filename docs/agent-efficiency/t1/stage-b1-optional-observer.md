# T1 stage B1 — disabled optional CALL_ONLY observer

2026-11-19. Scoped implementation task contract under issue #23 approval 6952955719 and the owner's request to accelerate independent authorized work. Files: adapter-sdk/call-telemetry.ts (isolated telemetry types/queue), ManagedModelProviderExecutor optional constructor hook and clone propagation, adapter-sdk export, provider-free test-harness and npm test registration. No shared-types, task contract, Cost Guard interface/result, provider retry, scheduler, gateway HTTP or production composition changes. A6 storage/readers shipped separately on main 6af49ea with CI 44418076081 SUCCESS 5/5 while this slice was built.

No observer is created by existing runtime constructors. Enablement requires explicitly injecting a server-owned CallTelemetryObserver instance with a fixed project, environment, separate HMAC key/version and private async delivery callback. There is no worker/request option, env auto-enable, provider credential use or SQL transport installed. withProviderConfig preserves an explicitly supplied observer. stop() disables enrollment/delivery, aborts the current transport, discards queued events and clears this instance's key copy; it never deletes prior evidence. The operator must retain protected historical key material separately for the agreed retention period.

Managed execution runs the existing generation validation, render/pricing and Cost Guard preflight unchanged. After preflight returns, it allocates a server invocation ID and enqueues CALL_ONLY registration before any provider request (a blocked preflight instead emits its blocked ledger candidate without calling the provider). The template HMAC is SHA-256 HMAC over a domain tag, environment, project, key version, prompt ID/version and the same rendered fingerprint used in existing ledger fields. It is not a plain prompt/request hash; raw prompts, variables, outputs, credentials, errors and plain fingerprints are not enqueued. Handles are frozen and instance-local WeakMap entries; copying an invocation ID cannot forge a handle. No lease/generation authority is inferred from task/session IDs.

Successful provider completion feeds only rawUsage into a candidate syntax filter. It accepts the already-approved T0 Anthropic/Google key sets, converts safe nonnegative integer numbers or canonical decimal strings into exact strings, and rejects unknown keys/getters/null/nesting/fractions/unsafe numbers/over-30-digit values. OpenAI has no candidate schema and accepts only an empty object. Invalid/missing usage becomes an empty unavailable observation with usage-missing. Provider failures emit a normalized provider-rejected marker, never the exception or normalized estimated usage. Cache/thinking equations and current endpoint accounting remain unverified; every usage event has canonicalStatus unavailable. No provider-spec verification or canonical mapping is claimed in B1.

The executor also emits **ledger_candidate**, not settlement, after each existing finalization return: allowed, preflight blocked, post-call blocked, provider failure, structured validation failure and deferred domain failure. This distinction is required by the source: product-pipeline/pipeline-service.ts and planning-service.ts invoke commitAllowedLedger inside withRlsTransaction, and later artifact writes can still roll back that ledger. No ledger candidate proves commit durability. A future trusted transport/reconciler must read the exact durable row and validate identity before using A5 link_ledger; it must not assume the candidate means the SQL transaction committed. No telemetry operation retries a model call or alters transaction semantics.

All hooks are synchronous, guarded, bounded local enqueue work; no observer I/O is awaited on the execution path. Delivery starts on a later event-loop turn. Capacity includes queued and in-flight events: <=1,024 events/16 MiB, each <=16 KiB, batches <=100. Events expire after 60 seconds on a monotonic clock; one background delivery attempt is made per batch (below the approved maximum of three). A delivery deadline defaults to 1 second and cannot exceed 60 seconds or the batch's oldest event deadline. On timeout the observer aborts and disables itself, dropping queued work. A transport that ignores abort retains at most one bounded in-flight batch and cannot trigger overlapping attempts; memory is released if it eventually settles. Transport exceptions are consumed with numeric local failure/drop counters, never raw logs. These counters do not prove complete coverage. The callback must be trusted, asynchronous/nonblocking and honor abort; this same-process design cannot preempt arbitrary synchronous CPU blocking inside a callback. No hard process-isolation or production-overhead claim is made.

Coverage remains explicitly incomplete. Pre-render/preflight exceptions precede enrollment; direct LiveModelProviderClient.complete and evaluateIndependentReviewWithLiveModel bypass this optional executor hook. Deferred handles may be abandoned, candidates may roll back, queues may overflow, processes may exit before an unref'd delivery runs, and a failure marker may itself be lost. There is no independent dispatch/in-flight inventory in this slice, so task-level enrollment and baseline eligibility remain disabled. No mandatory dispatcher/journal or new execution route is introduced to conceal these gaps.

Provider-free tests subclass the existing client to return fixtures (no HTTP/provider calls). They compare observer absent versus recording, rejecting transport, overflow, stopped observer and synchronous hook faults on allowed/preflight/provider/validation/domain/postcall paths: same parsed result/error type, original provider exception where applicable, token/cost totals, ledger status and provider count. Captured IDs must match the actual ledger IDs, but remain candidate events. Additional tests cover exact counters, canary exclusion, HMAC domain separation, forged handles, byte/event limits, <=100 batches, one attempt/no provider retries, a hanging abort-ignoring transport and another model call completing while that transport is still hung. Existing M6A transaction rollback tests remain regression evidence; B1 does not claim an after-commit observer integration test.

Remaining: authenticated SQL delivery/read deadlines, durable candidate reconciliation and identity/HMAC evidence, pinned provider mapping matrix/fixtures and streaming normalization, observer DB-down/crash/transaction integration/load measurements, lifecycle authority/transition rules, independent coverage and deterministic reports. T1/S0-B acceptance, real baseline samples and T2 spending remain separate gates. No production runtime collector is activated by this commit.
