# T1 stage A2 — service/project authority

2026-11-18. Scoped implementation task contract under issue #23 approval 6952955719: extend A1 with operator-maintained service identity bindings, typed call-only registration and bounded metadata reads. This is part of stage A, not completion of T1-A or T1. A1 review 210562455 accepted the foundation; its composite unique key is intentionally available for later project-scoped telemetry references.

Migration 0018 adds `telemetry.service_projects`. A database administrator provisions a dedicated LOGIN principal, grants the appropriate NOLOGIN service group and records the principal's OID **and** name, project and capability. No login, credential, membership or binding row is provisioned by this migration. Runtime roles cannot edit the registry. Role rename/recreation requires explicit reauthorization; stale identity rows fail closed. Provision only after ordered migrations; do not replay the initial 0017 role-collision checks after service memberships have been provisioned. Use a migration ledger for deployment.

Authorization uses authenticated `session_user`, membership and the operator registry, never app GUCs, caller-supplied principal identity or `current_user` inside SECURITY DEFINER. Elevated logins and principals with app_runtime membership are rejected. Service connections must use their dedicated login; an app_runtime pool cannot impersonate them. FORCE RLS constrains the non-login function owner to authorized projects. Admins remain trusted provisioning authorities. Removing a registry row takes effect in a fresh statement under the normal READ COMMITTED isolation level; long-running snapshot transactions must be terminated during emergency revocation.

`register_call` accepts bounded call metadata and a server-generated invocation UUID supplied by the future trusted service. It always stores CALL_ONLY, computes the immutable binding digest in SQL and relies on project-scoped foreign keys. Identical retries return the same ID without mutation; conflicting reuse fails. It cannot claim lifecycle authority, supply a digest or upgrade to TASK_BOUND. UPDATE/DELETE/TRUNCATE remain forbidden. `read_calls` exposes only ID, creation time, binding state, provider and model; keyset pagination requires a complete timestamp/UUID cursor and limits pages to 1–100 rows. Protected prompt references and digests are not returned. Both entry points use fixed pg_catalog search paths and separate role grants; there are no direct table grants.

Acceptance: real PG17 migration/reapply and transactional SQL tests passed locally. Tests cover identical retry/conflict, spoofed GUC, unbound service, wrong-project reads/writes/FK, direct access denial, writer/reader separation, pagination bounds, stale principal name, app_runtime dual membership and registry revocation. CI runs the A1 fixture before migration 0018, then applies 0018 twice and runs A2 tests on PG16/17 before the full regression suite. Fixtures use actual session authorization and roll back all roles/data.

Remaining stage A: lifecycle/manifest, settlement, observations, quality/report tables and typed functions, composite negative tests and index scale evidence. Runtime hooks and collection are still absent; provider-free normalization/observation hooks follow in stage B, reconciler/reporting in C and readiness evidence in D. No provider spending, native VM changes, T2 activation or S0-B acceptance is implied.
