## Recommended source and staged delivery

Use normal, already authorized Software Factory work through the metered provider adapters as the primary cohort. Capture counters at the service/provider boundary and reconcile them with the durable ModelCallLedger, not agent-written scratchpads. Start with one supported provider/model/prompt version in an operator-approved environment with existing Cost Guard limits; expand only after proving the mapping. Do not generate paid calls merely to fill a quota. Production Codex CLI remains blocked until trusted metering exists; unrelated personal Claude Code/Codex conversation histories are outside this proposal.

## Minimal trusted event contract to approve at T0

Proposed immutable per-call observation includes: schema version; service-generated event ID; existing ledger call ID; provider request ID when supplied; verified project/task/pipeline/cost-session identifiers; execution ID and lease epoch/takeover generation from the service's validated routing context; lifecycle attempt/retry/handoff group; service timestamps; provider/model and normalization/pricing version; prompt-builder/version and prompt hash; call outcome; counters; provenance and missingness. Do not trust caller-provided execution identity or infer generation from task ID/time proximity. A model call with no authoritative worker execution (for example planning stages) records `executionBinding=not-applicable` with its verified pipeline/stage context, and is not eligible for execution handoff metrics.

Counter fields are independent nullable nonnegative decimal integers: input total, uncached input, cache-read input, cache-write input, output, provider-reported total when available. Store reported billing amount/currency separately from price-table-calculated cost and existing estimated cost. Label their provenance `provider-reported`, `price-table-calculated`, `estimated`, `unavailable` or `not-applicable`; null never becomes zero. Existing actual_cost_micro_usd is calculated by the price table and is not automatically an independently settled invoice. Keep native provider field names and mapping version in an allowlisted numeric envelope; retain no arbitrary raw response.

Persist numeric usage before rawProviderUsage leaves the provider boundary. The current cost-guard extractor combines Anthropic cache creation/read with input; do not try to reconstruct split counters from a total later. New provider mappings must have explicit tests showing whether cache counts are subsets or additive; subtract cached counters only for a mapping that proves this relation. An unsupported/absent provider field stays unavailable. Tokens and cost units cannot be mixed; streaming incremental frames must be accumulated according to that provider's semantics exactly once, not summed as if each cumulative frame were a delta.

Idempotency binds `(ledger call ID, observation kind, revision)` to a digest: identical retry is a no-op; conflicting payload is quarantined/failed for review. One actual retry that incurs new usage has a new call ID and a linked attempt. Timeout/abort/partial stream preserves any authenticated known usage and explicit unknown remainder; absence of a terminal response cannot erase known spend or be called zero. Telemetry cannot replay a model call, mutate reservations, change cost authorization or substitute for the Cost Guard. A failure to persist telemetry makes the observation incomplete and ineligible for verified metrics; it must never produce a green budget or silently retry a chargeable action.

## Prompt layers, checkpoint and first meaningful action

The trusted prompt builder records L0/L1/L2 version/hash, declared tokenizer/version and its measured local token counts before submission. Those are **local prompt composition measurements**, separate from provider billed/cache tokens. If the provider exposes only aggregate caching, layer-level billed/cached counts remain unavailable. Do not distribute a cached total across layers by character length, byte ratio or guessed attribution. A stable prompt prefix alone does not prove a cache hit or saving.

For handoff, the service records transfer time, new validated generation and a trusted first action receipt tied to code-state fingerprint: a successful scoped source edit or a completed required verification operation counts, while reading a memo, searching, or an agent saying it started does not. Reject stale-generation actions and stale SHA/fingerprint test proof. Sum actual observed model tokens from takeover through that first qualifying receipt, including failed/resumed calls in that window; report missing input/cache/output separately and leave the metric unavailable if required totals are incomplete. A task's live old generation cannot contribute trusted receipts to the new generation. Definitions require checkpoint observer integration under P1 review, not a label added to an untrusted worker event.

## Representative cohort and analysis plan

Before observing spend, register task scope/risk and label S (bounded single package), M (approved cross-package feature) or L (security/recovery/schema/broad architecture). Keep provider/model/prompt version fixed within a comparison stratum. Include failures, retries, takeovers and reviewer-requested rework; never select only successful cheap calls. Assign a stable lifecycle ID through merge/abandonment, record observation cut-off and unresolved tasks as censored. Total effective cost includes all known calls in that lifecycle; an incomplete bill is a lower bound, not a complete total. Pre-instrumentation tasks stay in a separate historical cohort unless complete attribution can be proven.

Initial collection target: at least 30 complete task observations per S/M/L cohort **within a comparable stratum**, plus explicit counts for incomplete/censored tasks and task/provider mix. This is a proposed operational minimum, not statistical proof; if samples are sparse, report the distribution and withhold a budget rather than pool incompatible strata or drop heavy tails. Compute empirical nearest-rank P50/P75 on complete tasks, state sample size and quantile method, and show tail/max plus missingness. Cache hit ratio uses a denominator justified by the provider mapping; unavailable splits have no ratio.

Report independent quality with fixed denominators: first-pass review approval among first review submissions, missing requirements, omitted mandatory checks, fail-closed/security regressions, rework cycles and time to resume/handoff/rework. An independent reviewer/test receipt supplies outcomes; the agent cannot label its own success. Baseline is observational: no claim that caching/context changes caused savings without matched scope/model/quality comparison. The later optimization must preserve required validation and roll back if quality guardrails worsen.

## Access, retention and acceptance before pilot

Write access belongs to the existing trusted service identity via a narrowly scoped new append-only path, not agent/worker credentials. Project-scoped reads preserve existing authorization/RLS; no cross-project dashboard or general file/path API. Review the schema/ACL/immutability/backup/export design before T1. Keep service observations distinct from existing budget-denial and spending authority. Raw prompts/completions, auth headers, provider keys, signing material and personal transcripts are never collected. Export only approved counters, pseudonymous task/call references and version/hash metadata; pseudonyms remain access-controlled.

Proposed retention: 30 days for detailed counter records and 90 days for aggregate baseline summaries, subject to owner/team decision and existing evidence obligations. Retention deletion must use an approved operator path and must not delete required ledger/security evidence or weaken append-only runtime permissions. No deletion job is introduced by this proposal. Raw provider responses are transient; only the reviewed allowlist is persisted. Collector size/rate bounds and backpressure must be explicit in T1; overflow records missingness, never unbounded payload logging.

Pilot acceptance must prove: authenticated generation attribution; cross-project/worker forgery denial; duplicate/conflict handling; partial/aborted/streaming usage; exact large integers; cache subset/additive mapping; estimated versus known usage; unavailable layer attribution; no secret fields; no budget/recovery side effects; observer/fingerprint authority; and reconciliation of every collected call with its durable ledger/outcome. Run provider-free tests first, then separately authorized live samples. Publish source SHA, mapping version, sample window and coverage report. Team owns S0-B/checklist acceptance; a tested collector with zero real samples is still not a baseline.

Recommended review decision: approve T0 scope with the primary metered-adapter cohort and the staged plan; request a concrete T1 schema/authority contract next. No S/M/L number or production optimization should be enabled from this document alone.
