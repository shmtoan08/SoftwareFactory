## 2. Server-created call binding and generation fencing

Trusted ingestion is not proof of trusted attribution. At **server call creation, before dispatch**, the service derives a binding from verified routing/assignment state: project, task, execution ID, lease epoch/generation, lifecycle segment, ledger call ID and provider/model/prompt version. It records the binding's schema version, service timestamp, immutable binding ID and integrity digest under service-only authority. No worker, agent, provider response or client parameter can choose/change these fields. A verified task relationship must be a service-owned reference, not an inferred join by task ID, timestamp or proximity.

T1 must specify the linearization point: validate live generation and register the immutable call binding atomically against the same authoritative lease/generation record used for admission. A concurrent takeover either occurs before this point (old-generation registration is rejected) or after it (the already admitted call remains bound to the old generation). A stale worker cannot mint a new valid binding or current-generation receipt after transfer. Merely signing an agent-supplied execution ID or stamping generation when a response arrives is insufficient. If current architecture cannot prove this relation, the observation is **call-level only**, excluded from task lifecycle totals/percentiles; do not change core contracts implicitly to hide that gap.

A late provider response to an already bound old-generation call is settled by the trusted service against that **original binding and ledger call ID**. It never moves to the new generation, never validates a current lease/checkpoint, and never authorizes another action. Such historical usage can contribute to the original task lifecycle's cost/token accounting when its provenance and mapping are complete; it is not a new receipt created by the stale agent. Unbound or conflicting late responses are quarantined as normalized metadata only, with attribution incomplete. T1 tests must cover responses on both sides of the transfer linearization point and delayed duplicate/conflicting settlements.

An immutable event envelope contains only reviewed fields: event/binding/ledger IDs; verified scope and lifecycle segment; service timestamps; provider/model; prompt ID/version plus protected fingerprint reference; mapping/pricing versions; normalized outcome/error category; canonical counters/status; numeric provider-counter allowlist; attribution status/reason and provenance. Provider request identifiers are optional protected references, not routing authority. Planning calls without a proven task execution binding remain in a separate call/pipeline report; they cannot be counted as representative task lifecycle observations.

## 3. Canonical tokens and provider mapping

Each counter is a nullable nonnegative decimal integer string. `canonicalInput` counts logical input exactly once, including cache categories according to the verified mapping. `canonicalOutput` includes visible output plus charged reasoning/thinking exactly once where that relation is proved. `canonicalTotal = canonicalInput + canonicalOutput` is emitted **only** when both are complete and the mapping proves that cache, reasoning and any provider-reported total are reconciled without overlap. A reported total is a separate counter, not automatically canonical and never added to input/output again.

| canonicalStatus | Meaning | Baseline eligibility |
|---|---|---|
| available | Verified mapping; terminal usage complete; input/output/total exact and reconciled | Eligible only if attribution and the whole lifecycle are also complete |
| incomplete | Verified mapping but partial/aborted/missing final counters or reconciliation/collection gap; retain known components, leave total null | No complete-task percentile; report known lower bound/missingness separately |
| unavailable | Mapping unverified/unsupported, ambiguous cache or reasoning relation, unsafe numeric value, or no usable counters | No canonical total/complete-task percentile; retain only permitted observations with reasons |

No null becomes zero, and a known subset/lower bound is not called a complete total. A signed service envelope does not upgrade an unverified provider mapping to available. Independently reported billed amount/currency, price-table-calculated micro-USD and estimated cost are distinct provenance fields; current actual_cost_micro_usd is not assumed to be a settled invoice.

**T1 provider mapping matrix is mandatory**, keyed by provider, exact model, endpoint/API version, stream mode and mapping revision. It must enumerate the exact numeric schema/units, cache subset versus additive equations, reasoning/thinking inclusion, final versus cumulative/delta events, reconciliation rules and verified fixtures/spec references. Every row starts **UNVERIFIED → canonical unavailable**; only independently reviewed mapping evidence can change it. Pilot candidates below are not verified mappings.

| Candidate provider schema to verify in T1 | Explicit numeric allowlist for that schema | Required proof; default until proved |
|---|---|---|
| Anthropic Messages usage object | `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`; each optional nonnegative integer, unknown keys rejected from stored envelope | Whether cache categories are additive to base input; whether thinking is already inside output and whether a separate counter is exposed. Unknown thinking inclusion makes canonical output/total unavailable |
| Google GenerateContent usageMetadata | `promptTokenCount`, `candidatesTokenCount`, `totalTokenCount`, `cachedContentTokenCount`, `thoughtsTokenCount`; each optional nonnegative integer, unknown keys rejected from stored envelope | Cache subset relation and whether candidates exclude/include thoughts; reconcile total with all charged components. Do not inherit the current normalizer's total-minus-input fallback as proof |

The allowlists are proposed parser schemas, **not claims that every candidate model/API returns every key or has these exact accounting relations**. T1 must verify/correct the schema against the pinned provider contract before permitting that row; otherwise it remains unavailable and cannot enter T2's canonical cohort. Missing optional counters retain a reason, including `not-exposed`, `not-applicable` only when proved, or `missing`. Keep a separate nullable `reasoningThinkingTokens` with its inclusion rule (`included-in-output`, `add-to-output`, `not-applicable`, `unverified`); never add it twice. Aggregate output can be canonical without a separate reasoning count only when verified provider semantics prove that aggregate already includes the charged component.

Streaming receipts are deduplicated by server call binding/event identity and folded according to the matrix: terminal snapshots replace corresponding cumulative counters; true deltas are added once. No sum of repeated cumulative frames, cache categories, reasoning or totals without proof. Partial streams/abort/timeouts preserve known permitted counters and explicit missing remainder; absence of final usage never means zero. Transport retries of telemetry do not retry the model call. Each separately chargeable execution retry has a distinct existing call ID under the original lifecycle and its own binding.

## 4. Observation failures leave execution semantics unchanged

Telemetry is a **pure observer**. It cannot replay a provider call, retry a chargeable action, change reservations/Cost Guard, refresh or revoke leases, transfer generation, change scheduling, or turn a failed action into success. Existing execution authorization, lease fencing, model-call and billing/error behavior remain authoritative and unchanged.

If binding/observation persistence, normalization, queueing or export fails, **execution continues or fails solely according to its existing semantics**. The metric fails closed: mark that observation/lifecycle incomplete and exclude it from verified baseline, never invent a successful receipt or green budget. Do not make execution wait indefinitely for an observer or change provider retries to recover telemetry. Independently existing Cost Guard failures retain their existing effects; the observer neither replaces nor weakens them.

T1 must define a bounded asynchronous delivery path and idempotency key `(call binding ID, observation kind, revision)` with digest checks: identical delivery is a no-op, conflicting delivery is incomplete/quarantined for review. A service-owned expected-call inventory/ledger reconciliation detects missing observations even when the collector cannot persist its own failure marker. A delivery or crash gap can be repaired from existing authoritative records without calling a model again; if proof is unavailable, it remains incomplete. Bounded queue exhaustion drops eligibility with an explicit coverage gap, not unlimited buffering, secret logging or execution blocking. Pilot suspension concerns future enrollment/collection under operator control; it does not silently interrupt running tasks because telemetry failed.

## 5. Locked size rubric and separate risk classification

Before the first chargeable call, the operator signs a cohort manifest bound to the task_contract version/protected fingerprint, lifecycle ID, planned scope, size and risk. These are **proposed telemetry metadata**, not newly authorized task_contract fields. T1 must obtain explicit core-contract scope if storage requires any signature/schema change. Agent self-labels are not authoritative.

Count distinct planned tracked source/test/doc/config paths and workspace packages to be touched. Include root/non-workspace paths in file counts and mark them separately; do not count generated runtime output as source files. Planned globs need a finite reviewed path inventory or an enforceable upper bound before classification.

| taskSize | Objective planned scope, frozen before usage |
|---|---|
| S | At most 1 workspace package and at most 5 tracked file paths |
| M | Not S, at most 3 workspace packages and at most 20 tracked file paths |
| L | More than 3 workspace packages or more than 20 tracked file paths |
| unclassified | Missing/unknown/unbounded planned counts; no S/M/L baseline eligibility until fixed before calls, but ordinary execution is unaffected |

Risk is a separate multi-label field with explicit booleans: `schemaMigration`, `authRls`, `securityIsolation`, `recoveryLease`, `publicContract`, plus `ordinary` when none apply. Thus a one-file auth fix can be **S + authRls**, rather than mislabeled L. Record the manifest ID/version and operator principal at task creation/contract approval, before observing usage. Labels cannot be reassigned after spend to improve distributions. A scope amendment retains the original size/risk labels, records a deviation and approved new contract version, and reports actual counts separately; keep deviations visible in the original cohort and denominators rather than cherry-picking them away. A prospective new task lifecycle gets its own pre-run classification.

## 6. Lifecycle completion, outcomes and censoring

A stable root lifecycle includes every linked execution/attempt/retry/takeover/rework and chargeable call through merge or explicit closure. T1 must define service-owned membership and closure records; do not guess links from time proximity. Completion requires **both** a terminal workflow disposition and a settled inventory: no active/uncertain call, linked execution, pending retry/takeover/rework, unprocessed usage receipt or unresolved accounting gap. A terminal task label alone is insufficient. Reconcile expected calls against ledgers and observations before emitting a complete total.

`MergedAndCompleted` is the current successful task outcome; `ManualIntervention` is a hold, not automatic failed completion. Proposed telemetry closure outcomes `failed-terminal`, `abandoned-terminal` and `cancelled-terminal` require an explicit authorized workflow/operator disposition and settled linked work, not invented TaskStatus values. With complete usage they are **complete outcome classes reported separately** from success; do not discard them or silently pool them when deriving success budgets. Cancellation with a running/unknown call remains incomplete until settled.

Reopen preserves the root lifecycle and prior spend and adds a versioned segment; it never creates a duplicate independent sample. Withdraw/revise the earlier terminal summary with provenance, while historical reports remain reproducible at their cut-off. Do not count both the old closed segment and the reopened root as two tasks. A cancelled/reopened task's cost includes all segments and stays in its original pre-run size/risk stratum; final disposition determines its outcome class.

Proposed maximum baseline observation window: **30 calendar days from the first chargeable call**, with a UTC report cut-off. An unsettled lifecycle at that point is right-censored/incomplete with known usage and missing reasons; T3 reports it immediately in the denominator rather than waiting indefinitely. It may settle later in a separately labeled late-completion report linked to the original sample; never silently rewrite an old P50/P75. A completed task with missing telemetry is incomplete, not a complete zero. Pre-instrumentation tasks are a separate historical cohort unless every call/binding/mapping can be proved complete. Censoring ends a reporting window, **not the workflow or retention lifecycle**.

Collect at least 30 complete observations per size/provider-model-prompt-mapping/outcome stratum for the proposed initial operational baseline, and publish incomplete/censored/unclassified/deviation counts and tail/max. Sparse strata stay sparse; do not pool incompatible models/risks/outcomes or suppress heavy tails merely to reach 30. Use empirical nearest-rank P50/P75 on eligible complete totals, publish sample/window/quantile method and quality outcomes from independent review/tests. No numeric budget or causal saving claim follows automatically. Required tests/security gates stay intact.

## 7. Sensitive fields, access and retention

Prompt fingerprints are sensitive metadata, including fingerprints of templates and task-specific context. Prefer **domain-separated keyed HMAC-SHA256** with an operator-owned secret in the service's protected key store; store only key version and scoped reference, never the key. Prevent low-entropy prompt dictionary/linkage attacks: no public plain prompt hashes, raw task-contract text or rendered content in telemetry exports. Existing immutable ledgers/hashes are not rewritten by this proposal; T1 specifies the protected join/reference without copying their sensitive fields into general telemetry. Rotation/read access/export policy must be reviewed.

Do not persist raw error bodies, raw exceptions/stack traces, raw provider responses, prompts/completions, auth headers, keys or personal transcripts. Only finite normalized error categories/codes, for example `provider-timeout`, `provider-rate-limited`, `provider-rejected`, `transport-failure`, `usage-missing`, `mapping-unverified`, `attribution-incomplete` and `observer-persist-failed`, with no arbitrary message/detail string. T1 defines the complete bounded enum. Numeric provider objects must match the specific schemas in §3; copying arbitrary keys from rawProviderUsage or a name-only generic usage object is forbidden. Unknown fields are dropped from collection without logging their content, with a normalized schema/mapping reason.

Writes use a narrowly scoped append-only trusted service path; agents/workers cannot write/overwrite attribution or observations. Reads preserve project authorization/RLS. Treat pseudonymous call/task/provider request references as sensitive and access-controlled. Export approved aggregated counters/provenance only; review small-cohort disclosure. T1 must set payload/queue/rate bounds, access and immutable evidence design explicitly before collection.

**Revised proposed retention for team decision:** detailed telemetry **90 days from final lifecycle closure/settlement**, aggregates **365 days from the corresponding report's finalized cut-off**. These replace the original 30/90-day proposal; neither is active or final until team accepts this revision. Reopening moves the detailed retention clock to the new final closure; never delete old segments while linked work is open. A lifecycle censored at day 30 remains open for retention, so censoring cannot trigger deletion. Escalate long-open lifecycles/capacity to the operator; no automatic abandonment or premature expiry. Unattributed call-only records use their own final call settlement as the retention anchor, clearly separate from lifecycle records.

Deletion needs a separately approved operator/retention path and legal/evidence holds. **Never delete ModelCallLedger, security/audit evidence or required checkpoint records under telemetry retention.** Runtime append-only permissions are not weakened for a future janitor. No deletion job or storage migration is implemented here.
