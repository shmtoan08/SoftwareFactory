## Safe control path and implementation

`NativeLimaWorkerConnector` implements the existing `ExecutionTargetConnector`, so an operator may explicitly register it in CoreApi `executionTargets.connectors` under a dedicated target key. Existing Postgres-backed assignment/profile/lease/controlled-import checks remain in the broker. It is not automatically installed or enabled by this change. The guest must already be running and operator-provisioned: the runtime calls only `limactl --version` and `limactl list --json <exact instance>`. It never creates, downloads, starts or stops a VM, invokes guest shell/SSH, executes arbitrary diagnostic argv or falls back to a default instance. Legacy native start/diagnostic guards remain unchanged.

The pinned native inspection schema is Lima **2.3.0**, independently checked against CLI version and instance-creation metadata (official metadata may include `v`). This does not silently repurpose the foundation's older v2.0.3 shell/start semantics. Sources: [release](https://github.com/lima-vm/lima/releases/tag/v2.3.0), [instance fields](https://github.com/lima-vm/lima/blob/v2.3.0/pkg/limatype/lima_instance.go), [resolved defaults/plain behavior](https://github.com/lima-vm/lima/blob/v2.3.0/pkg/limayaml/defaults.go), [creation version metadata](https://github.com/lima-vm/lima/blob/v2.3.0/pkg/instance/create.go), [CLI version normalization](https://github.com/lima-vm/lima/blob/v2.3.0/cmd/limactl/main.go). Later versions require a reviewed profile/schema update, not a permissive version range.

Registration requires `sf-native-*`, explicit dedicated-instance opt-in, private owned canonical control HOME/LIMA_HOME/instance roots, pinned executable SHA256 and safe ownership/modes. No personal ~/.lima or HOME default is accepted. Effective JSON config is hash-pinned and rechecked before each health/action and after result retrieval. Required policy: native-arch VZ, plain mode, no host mounts/copyToHost/additional disks/networks, agent/X11/dot-SSH forwarding off, containerd off, one local preverified image with its registered digest, exactly one static TCP forward from host127.0.0.1 to guest127.0.0.1 HTTPS. Port ranges must be singletons; socket/reverse/wildcard forwards fail closed. Image SHA is registered provenance, not a measurement of the running root filesystem.

Worker traffic uses the existing HTTPS protocol and dedicated HMAC key/nonce/identity/lease checks. No production HTTP exception, TLS bypass, redirect or SSH config/control socket is introduced. Guest TLS certificate must validate for127.0.0.1 under a dedicated operator CA loaded before Node starts. The host bridge pins signed instance/source/profile/boot identity, requires matching native architecture and withholds even valid artifacts if a reboot/registration change is detected after execution. A transport/identity failure is uncertain: no automatic retry or VM restart; existing durable worker journal holds remain authoritative.

`createNativeWorkerService` is a root bootstrap inside the guest: source root must be its actual module location, clean at the registered source SHA; tracked inputs and ancestor roots must have safe ownership/modes. State/workspace/source roots cannot overlap. Guest host-share mount types are rejected. Existing strict `LinuxWorkerEndpointRunner` performs cgroups/namespaces/subreaper/UID-drop execution and cleanup. Additional native masks hide source, `/run` (Lima agent/control sockets), homes and native service config; task workspace is outside those paths under `/var/lib`. No new emulator switch exists in the service. Health adds optional signed runtime measurements to the existing protocol; clients without that field remain compatible, but this native connector requires it. Measurements are service assertions bound to operator-owned credentials, not hardware attestation or a replacement for kernel acceptance.

`createNativeAcceptanceWorkerService` and `native-vm-guest-service.ts` supply a deterministic provider-free adapter that writes only `src/value.txt`. This tests real transport/kernel execution without a paid model. It does not enable production Codex or claim model capability. Production adapter selection remains an explicit later operator configuration with existing Cost Guard policy.

## Dedicated host preparation (operator step, not executed by this slice)

Mac checked: Intel x86_64, macOS15.7.9,16GiB RAM, hypervisor support1; no limactl in PATH. No VM or OS package was installed/started. Existing issue16 restrictions against automatic provisioning still apply. Use an exclusive test instance, private state root and private CA/key; do not import a personal VM or share host HOME/repository/credentials.

1. Operator installs/verifies Lima2.3.0 and records resolved binary SHA256. Create private0700 control HOME/LIMA_HOME. Verify a local Linux x86_64 image by SHA256; record image origin/digest. Only one static TCP rule is allowed: host127.0.0.1:56620 -> guest127.0.0.1:24443. Choose `proto:tcp`; never expose0.0.0.0. Creation/start are explicit operator provisioning commands outside managed runtime. Runtime checks the resolved config, not merely this YAML intent.
2. In the guest, operator installs Node>=22.6, Git and native C compiler, verifies cgroupsv2 and required kernel namespace/mount facilities, and provides a dedicated delegated cgroup root containing `software-factory.slice` with cpu/memory/pids enabled. Preserve the established strict Linux acceptance setup; no Docker/socket fallback. Do not alter another test run's delegation.
3. Clone exact source SHA to root-owned `/opt/software-factory`; `npm ci`; all tracked files/root ancestors must be root-owned and not group/world writable. This includes running the service from that checkout, not pointing sourceRoot at an unrelated clean tree. Keep public baseline repo, state0700 and workspaces0755 in separate root-owned `/var/lib/sf-native-*` locations. A baseline repo contains committed `src/value.txt`=`baseline\n`, and the service registry pins its commit. No host source mounts.
4. Configure a guest TLS proxy on127.0.0.1:24443 to the worker on127.0.0.1:24444. Limit routes to `/health` and `/execute`, bound requests to the existing protocol limits, permit timeout up to125s, disable request-body/key logging. Use a dedicated cert with IP SAN127.0.0.1 and operator CA; no agent forwarding. Worker service signing key is unique to this guest, random>=32bytes; it is not a Factory/DB/Git/model key. TLS keys and configs live root-only under `/etc/sf-native`.
5. Capture `limactl list --json sf-native-acceptance` into a private operator file using the private HOME/LIMA_HOME; review effective policy and hash **canonicalizeJson(entry.config)** via shared-types SHA256. Registration profile is exactly `{instanceId,sourceSha,imageSha256,limaConfigSha256}`. Host and guest receive the same profile, never secret-bearing resolved config in public logs. 6. Write root-only0600 guest service JSON implementing `NativeWorkerServiceConfig`: profile, sourceRoot, principalId/workerId, tenantNamespace, stateDir, worktreeBaseDir, baselineCommitRegistry, cgroupRoot, signingSecret and port24444. Launch from the source checkout with a clean environment and fixed PATH, e.g. `node packages/test-harness/src/native-vm-guest-service.ts /etc/sf-native/service.json`. This is only the fixed provider-free acceptance service. It probes real kernel health before listening and exits on invalid source/profile/kernel; stdout contains safe measurements, never the key. Supervise it as an operator-owned guest service and retain restart/HOLD state.
7. Host JSON (0600 in private0700 control directory) is `{bridge: NativeLimaWorkerConfig, baselineCommit}`. Set binaryPath to its canonical verified file, binarySha256, explicit limaHome/controlHome, dedicatedInstance=true, profile, guestHttpsPort24443 and worker HTTPS endpoint/principal/worker/provider=`native-acceptance`/model=`provider-free`/dedicated signingSecret. Omit testOnlyEmulator and testOnlyLoopback; host acceptance rejects them. Signing secret must match only that guest's service.

This is an operator provisioning checklist, not evidence it was executed. Private JSON/key/CA files and raw Lima config must stay outside the repository and evidence receipts. Record actual image/config/binary digests rather than placeholder values; failure to configure a required facility keeps acceptance pending.

## Acceptance commands and evidence

From the exact clean root-owned guest checkout, with the private **profile-only** JSON and already-delegated cgroup root:

```bash
SF_NATIVE_SOURCE_ROOT=/opt/software-factory \
SF_WORKER_TEST_CGROUP_ROOT=/sys/fs/cgroup/DEDICATED_NATIVE_ROOT \
node packages/test-harness/src/native-vm-guest-acceptance.ts /etc/sf-native/profile.json
```

Runs actual strict worker smoke, measured bootstrap/host-control masking/replay, and the independent isolation suite. The existing strict TAP validator rejects incomplete summaries, failures, cancellation, skips or todo. Both logs and their hashes are recorded in a root-private `/var/lib/sf-native-evidence-*` directory with manifest source/profile/boot/kernel/arch/Node binding. A failure emits no PASSED manifest; partial logs are diagnostic only. Native coordinator-death, descendant timeout, cleanup and adversarial checks are inherited from these executed suites, not replaced with host CLI termination.

Operator securely copies only guest-manifest.json, worker.tap and isolation.tap to a private host evidence directory. Keep the guest service on the same boot/source/profile. From the clean matching host checkout:

```bash
NODE_EXTRA_CA_CERTS=/ABS/PRIVATE_CONTROL/native-test-ca.pem \
node packages/test-harness/src/native-vm-host-acceptance.ts \
  /ABS/PRIVATE_CONTROL/host.json \
  /ABS/PRIVATE_EVIDENCE/guest-manifest.json \
  /ABS/PRIVATE_EVIDENCE/NEW-host-receipt.json
```

No TLS-disable variables. The host independently verifies log hashes/strict summaries, source/profile/boot binding, signed HTTPS health, actual artifact result, durable replay and lease conflict. It verifies registration before/after action and records Mac version/kernel/arch/Node, normalized Lima version, binary/image/config digests and guest measurements. Output uses exclusive creation; no overwrite and no receipt in the source tree. Status `HOST_BRIDGE_PASSED` is a developer evidence result, not a team G7 decision. Aggregate the exact command/version receipts, safe logs/hashes, guest and host manifests with release/traceability evidence for team review. Windows/WSL2 needs an independently implemented/executed native path and receipts on the Windows host; this Lima slice cannot stand in for it.
