# Dashboard Slice 0 — Core API capability and read-only audit

Status: **PROPOSED — team approval required before Slice 1**. Tracker: [issue #20](https://github.com/shmtoan08/SoftwareFactory/issues/20). Audited source: main `305796031ac2f063e20efcb1692f6bd72743c9bf`, 2026-11-14 (Asia/Tokyo). No UI, schema, API or production behavior is changed by this slice.

## Audit method and boundary

Routes were traced through [Core HTTP handlers](../../core-api/src/http-server.ts), [authorization/service methods](../../core-api/src/index.ts), [pipeline service](../../../packages/product-pipeline/src/pipeline-service.ts), [planning/profile service](../../../packages/product-pipeline/src/planning-service.ts), [traceability builder](../../../packages/product-pipeline/src/traceability.ts), [memory store](../../../packages/database/src/index.ts) and [PostgreSQL repository](../../../packages/database/src/postgres-pool.ts). DTOs/statuses were checked against [shared types](../../../packages/shared-types/src/index.ts). This is a source audit, not an assertion that a live production database or provider was exercised.

A GET verb is insufficient evidence of read-only behavior. Here read-only means no domain mutation, lease renewal, execution/model invocation, reconciliation/recovery trigger or durable business-audit insertion. Authentication/RLS transaction setup, SELECTs, clock reads and existing operational HTTP telemetry are distinguished from domain audit writes. No promise of zero filesystem/network/observability I/O is made.

Classifications:

- **R0 — source-verified data read:** handler/service/store path performs reads/projection; eligible for the proposed allowlist, still subject to team approval and later runtime regression tests.
- **R1 — conditional, NOT allowlisted yet:** reads include host Git subprocesses or other behavior needing an explicit read-only boundary decision. Hide affected panels until approved or a separate safe projection is provided.
- **X — excluded:** mutating, externally active, absent, insufficiently scoped or missing required capabilities. Unsupported is capability metadata reported in this audit; the UI panel is hidden, not filled with placeholders or inferred values.

R0 is not blanket permission to fetch unbounded collections: the eligibility/scale column further restricts their Dashboard use.

All routes below are Core routes. `P=/api/v1/projects/{projectId}`, `S=P/pipeline-sessions/{sessionId}`, `T=P/tasks/{taskId}`. IDs must be encoded and authenticated project/session/resource ownership checked; URL IDs confer no authority. **R** roles are AUDITOR, DEVELOPER, PROJECT_APPROVER, ORG_ADMIN with valid signed auth and matching project membership and role. **A** roles are PROJECT_APPROVER/ORG_ADMIN. RLS is retained; neither frontend nor a web proxy may issue its own broader service credentials.

## Prohibited calls and implementation constraints

No POST/PUT/PATCH/DELETE calls in Dashboard v1, including lease sync/renewal, scheduler dispatch, execute-target, imports, verification, gate approvals, pipeline generation/freeze, CR apply, release issuance, CAS, budget resume or reconciliation. Dashboard does not call a similarly named method simply because it exists on CoreApiService or ControlPlaneStore; endpoint capability is the boundary.

No new schema/migration, Core API method, production config, model invocation, object URL, auth bypass or runtime activation is authorized by this audit. `HttpCoreApiClient` lacks dedicated convenience wrappers for some newer read routes; a future apps/web data layer may wrap existing R0 HTTP paths without adding API behavior. Never expose Core auth tokens in URLs, HTML, resource content, browser storage or telemetry; preserve existing server-side auth handling until an explicit client security design is approved.

## Unsupported items requiring team decisions

1. Project detail/name and global project discovery need an approved read projection if required; do not misuse A-only approval-center or treat session titles as project names.
2. Scalable work-item table with server session/stage/status filters and pagination is unavailable. The M6B bundle provides exact links but also executes Git/traceability and is unbounded. Need a separate safe, bounded reader or explicit scoped approval before Slice 2.
3. Native active agent instances, physical active execution counts and active-assignment lifecycle are not exposed. Neither is project health/workload percentage.
4. Project budget panels must remain hidden: GET P/budget has confirmed recovery/write behavior. Cost-session figures are a separate supported capability with strict scope labels.
5. Artifact downloads, project audit feed and full deployment-approval collection/lifecycle are not exposed. Do not synthesize backend URLs or pending/deadline fields.
6. R1 Git readers need a decision on supported trusted-repository/configuration and read-only execution boundary; source-level GET alone is not approval.

These are gaps, not permission to modify the production API. [Companion mapping proposal](./data-mapping-spec.md) defines display behavior only for verified/approved data. Team must confirm unsupported items and approve both Slice 0 documents before UI implementation, as required by issue #20.
