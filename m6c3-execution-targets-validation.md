# M6C-3 — Approved external execution targets

Baseline: `2216c12`; deployment reconciliation was accepted and [issue #11](https://github.com/shmtoan08/SoftwareFactory/issues/11) closed by the team. This slice adds operator-configured signed HTTP clients for Tier 2/3/4 and automatic mandatory verifier isolation for their assigned leases. M6C/G7 is still in progress.

## Operator setup and request flow

Apply migration `0016` after `0015`. Configure `executionTargets.connectors` through CoreApiService/createCoreApiRuntime dependency injection. The registry is empty by default; HTTP callers cannot choose URLs, keys, connector implementations or worker identities. Configuring a connector requires durable PostgreSQL; only an explicit in-process test flag permits the memory emulator. The CLI runtime does not load connector definitions from environment variables.

The SDK exports UserManagedWorkerHttpConnector, ProviderVmHttpConnector and RemoteSessionHttpConnector. Each makes actual HTTP requests to an operator-owned protocol-compatible endpoint. HTTPS, dedicated signing secrets of at least 32 bytes and fixed principal/worker/provider/model identity are required. Plain HTTP is restricted to explicit local emulator configuration. These are clients, not VM provisioning implementations, vendor cloud SDKs, remote sandbox supervisors or an HTTP server for WNA. An operator still needs a compatible remote service. A health response authenticates the configured endpoint's declarations; it is not an OS isolation attestation or proof of remote billing accuracy.

All paths below are relative to `/api/v1/projects/:projectId/tasks/:taskId`:

1. An approver/admin creates `POST /execution-target` with `profile_id`, `data_classification: "PUBLIC"`, and `public_context` (at most 16 KiB). The task must have no attempts/leases. The active DEVELOPER profile must name a registered external target and agree with the Stage 7 assignment, when present. The immutable approval snapshots profile identity/capabilities, contract hash, configured worker and the reviewed context. Detected credential patterns are rejected; the approving human remains responsible for accurate PUBLIC classification. Arbitrary secrets cannot be detected reliably by pattern matching.
2. A developer/admin/approver calls `POST /execute-target` with only a canonical UUID `execution_request_id`. Authenticated health/capability checks precede lease allocation. Existing project budget, dependency, concurrency and overlapping-file checks apply. Changing the approved profile or contract prevents a new dispatch. A lease and PENDING dispatch intent are persisted together.
3. A separate transaction claims PENDING as SENDING before the one remote execute POST. Concurrent/replayed requests share the same lease and durable intent. The outbound action contains only lease execution ID/epoch/deadline, task ID, base commit, allowed file patterns and the reviewed PUBLIC context. It contains no task title, full contract, repository location, source tree, environment or Factory/DB/Git/model credentials. A compatible endpoint must obtain any public baseline independently; private repository access is not implemented here.
4. The signed response must match configured identity, nonce, execution ID and epoch. Its bundle/patch/artifact DTO enters the existing controlled import validator; response size, paths, protected files, Git ancestry/tree and live lease checks still apply. IMPORTED requires the exact durable controlled-import receipt. Imports publish an isolated ref and never change main directly.
5. `GET /execution-target` and `GET /target-dispatches` expose project-scoped assignment and dispatch evidence to authorized read roles. The legacy direct lease endpoint and scheduler refuse assigned external tasks rather than dispatching them on a default worker. Factory-managed tasks retain their existing path; external execution uses the explicit broker endpoint.

## HTTP protocol

The endpoint base path receives POST `health` and POST `execute`. Requests contain `{schema_version:"sf-target-v1", nonce, action}`. Health action is `{}`; execute action is the bounded payload above, with lease UUID also supplied as `idempotency-key`.

Both directions use `x-sf-target-signature`, a hex HMAC-SHA256 over `sf-target-http-v1`, direction (`request`/`response`), exact URL pathname, nonce and SHA-256 of canonical JSON, separated by newlines. `signTargetProtocol` implements this format. Direction/path/nonce binding prevents reflected/replayed responses from authenticating a different request. Transport redirects are rejected; responses must be JSON and are capped at 16 KiB for health or 3 MiB for execute.

Responses contain `schema_version`, `nonce`, `target_type`, `principal_id`, `worker_id`, `provider`, `model`. Health additionally supplies `capabilities`, including `code-import-v1`, `idempotent-execution`, `lease-fenced-results`. Execute additionally supplies `execution_id`, `lease_epoch`, `submission`. Unknown response fields are rejected. Endpoint credentials are dedicated to this protocol and never reuse Factory authorization or repository credentials.

## Failure and isolation boundaries

A request that has reached SENDING is never automatically sent again. Timeout, transport errors and invalid remote results leave UNKNOWN or REJECTED; raw remote errors are suppressed. A process can die before sending after its committed claim, leaving SENDING. Existing receipts resolve lost completion acknowledgements to IMPORTED without another provider call. No receipt means the existing state is returned. Recovery of remote computation, cancellation and provider costs is not implemented. Lease expiry/revocation fences result import; it does not prove that a remote process stopped. Starting a fresh execution requires the normal lease/rework lifecycle and a new request ID; the operator must first investigate any uncertain remote effect/cost.

All assigned external targets, including Tier 2, require network-disabled Docker **runsc** verification and a pinned image digest. This conservative rule also covers Tier 3/4. The immutable assignment ID lives on the source lease, so changing mutable organization metadata afterward cannot reduce isolation. The Core API forces this policy; memory validation and PostgreSQL INSERT triggers reject weaker/missing provenance even through alternate import/verification entry points. Existing runsc availability checks fail closed without a subprocess fallback.

Migration 0016 adds FORCE-RLS assignment/dispatch tables and composite tenant FKs. Assignments have no runtime UPDATE/DELETE grants. Tenant-scoped assignment SELECT remains available to lease/import/verification triggers in gateway scope, avoiding an invisible-assignment bypass; INSERT requires Core API scope and the authenticated project approver. Assigned task contracts and lease target/request/worker/task/project/epoch bindings are immutable. SQL validates profile/contract snapshots, legal intent transitions, live claims and exact receipt provenance. Target evidence/audits contain hashes/IDs/static error codes, not dedicated endpoint secrets.

Existing project/task budget checks gate dispatch. This protocol does not provide per-model-call Cost Guard metering, remote token/cost telemetry or remote process cleanup. Codex-named provider/model connectors are explicitly blocked; the existing production Codex adapter block remains intact. A trusted operator must not register a paid opaque service under a false identity. No live model/provider/cloud execution was performed.

## Validation

- Focused suite: **6/6 passed, 0 skipped**, Node 24.16 / PostgreSQL 17.10. Local signed HTTP emulators cover all three clients, concurrent replay, strict HTTP/RBAC, signature/identity/capability/redirect/size/binding failures, secret/context rejection, protected-path import denial, profile drift, scheduler/direct-dispatch denial, lease revocation during execution, lost completion recovery and restarted intent handling.
- PostgreSQL probes cover immutable grants/bindings, gateway bypass attempts, raw SQL verification downgrade, tenant isolation, FORCE RLS and durable reads through a fresh repository. A child process exits after committing SENDING and before its remote call; a retry makes no execute request.
- Policy probes assert that Core API forces runsc/network isolation after profile edits; these probes deliberately stop before execution and do not fabricate successful verifier evidence. Real runsc enforcement remains independently exercised by the Linux gVisor CI job.
- Clean migration application/reapplication and the existing RLS-T1..T8 matrix passed. CI migration fixtures include 0016 twice on clean/historical upgrade paths.
- Full local regression: **137/137 passed, 18 suites, 0 failures/skips**, ~285 seconds. Lint/strict TypeScript/shell syntax: **150 inputs passed**; secret scan: **149 inputs, 0 leaks**. Exact source commit, completed CI evidence and reviewer acceptance are tracked in [issue #12](https://github.com/shmtoan08/SoftwareFactory/issues/12).

Remaining M6C-3 work includes concrete endpoint supervision/provisioning, remote resource accounting/cleanup, actual vendor deployment/fencing adapters, Firecracker, Lima/WSL2 backends, their isolation acceptance evidence and final G7 review. This slice does not mark those gates complete.
